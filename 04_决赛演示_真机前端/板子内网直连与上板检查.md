## 二、操作流程（含具体指令）

### 第 0 步 — 连内网 WiFi
单击系统托盘无线图标 → 选「小米主路由器」→ 输入 `test1234`。
确认拿到内网 IP（应 192.168.31.x）：
```powershell
ipconfig
Test-NetConnection 192.168.31.158 -Port 22
Test-NetConnection 192.168.31.158 -Port 8000
```

### 第 1 步 — 一键连通性检查（演示机）
把 `check_board.ps1` 存到本机，PowerShell 运行：
```powershell
powershell -ExecutionPolicy Bypass -File .\check_board.ps1
```
正常应看到：8000 端口 OPEN + `/health` 返回 status=ok + matmul 返回 `-1`。

### 第 2 步 — SSH 上板看服务（板内）
```bash
ssh uisrc@192.168.31.158        # 密码 5182
# 进入后跑一次部署检查（把 board_status.sh 传到板子）
scp board_status.sh uisrc@192.168.31.158:~/
ssh uisrc@192.168.31.158 'bash ~/board_status.sh'
```
重点看：① `ss -tlnp` 里 8000 是否监听；② `/health` 是否响应；③ `find` 出的 server_gazelle/run_ds3/weights 位置。

### 第 3 步 — 若 8000 未起，板上启动服务
```bash
cd ~                             # 或 cd 到 find 出的 server_gazelle.py 所在目录
sudo env OPTC_PORT=8000 python3 server_gazelle.py
```
注意：compass_sdk 会改 sys.argv，**必须用 env 传参，禁位置参数**；非阻塞看日志。

### 第 4 步 — 启动 demo 前端（演示机，直连板，无隧道）
```bash
cd 决赛提交包/04_决赛演示_真机前端
OPTC_HOST=192.168.31.158 OPTC_PORT=8000 HW_MODEL=model10 \
  uvicorn demo_hw.server:app --port 8100
```
浏览器打开 <http://127.0.0.1:8100> —— 状态灯应绿色「真机已连接（…192.168.31.158:8000）」。

> 若现场要求 web 端也能从其它机器访问，uvicorn 加 `--host 0.0.0.0`。

## 三、常见问题

| 现象 | 原因/处置 |
|---|---|
| 8000 端口不通但 22 通 | server_gazelle 未起 → 板上第 3 步 |
| `/health` 失败 | 板上服务进程异常/被抢占 → `ps aux` 看有没有他队进程 |
| matmul 返回异常非 -1 | 板子未校准/在坏窗口 → 需 fresh compass_cali + 放行判据 |
| 连内网后天桥/图片加载不动 | 内网无外网；先切回外网网络再用 DSH，或提前备好离线材料 |

## 四、与 demo 前端 v2 的衔接

- demo `OPTC_HOST` 默认 127.0.0.1，现场**指向 192.168.31.158** 即直连板；
- 判据③（真 MNIST canary）、④（EuroSAT mini-run）在 `/api/checks/` 下，四项全绿再开窗；
- 30min 窗口预算：校准~10min + 判据~5min + 跑批~15min（M10 默认 [0,200) ≈ 11min）；
- 逐列校准 json（`HW_CALIB_COL`）必须**同窗口**生成，跨窗口必失效（stale −12.5pt 实证）。
