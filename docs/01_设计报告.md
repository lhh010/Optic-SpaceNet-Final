## 1. 项目背景与目标

### 1.1 背景

复赛完成了 EuroSAT CNN → Gazelle 光计算的 **osimulator 仿真迁移**（三模型，gap ≤2%）。决赛目标：在 **Gazelle 真机**上完成模型族的端到端部署与**全量（5400 张 test）精度验证**，并回答三个工程问题：

1. **架构-硬件匹配**：何种结构（全 1×1 / 3×3 / 窄通道 / conv3s2 下采样）在真实器件噪声下表现最优；
2. **校准体系**：per-column 仿射校准 vs 逐列（per-channel）最小二乘校准（calibrate_col）的真实收益；
3. **器件热稳定性**：激光器/器件连续工作窗口与冷却策略（已实证：连续 ~2h 后热崩溃，0% 输出）。

### 1.2 设计目标

| 维度 | 目标 |
|---|---|
| 真机全量验证 | 每个部署模型在 EuroSAT test 5400 张上完成全量评测 |
| 真机 vs 干净参考 gap | 主模型（M4/M6/M10）≤ 3pt |
| 校准有效性 | 逐列校准相对标量真实收益 +1~2pt（C1 ABA，c3d，n=1000/配置：94.60 vs 92.60）|
| 器件保护 | 单次调用（含校准）< 30min、调用间 ≥5min 冷却、热崩溃可恢复 |
| 可复现性 | 全程日志/校准/权重/错误明细入库，判据与 SOP 文档化 |

### 1.3 核心设计思想：架构 × 硬件噪声联合设计（Round X0）

决赛模型族沿用 X0 轮结论：**v8 漂移鲁棒 QAT**（训练注入真机 probe 实测三组分噪声 ×1.5 余量）+ **1×1 光算层优先**（3×3 层 δW 结构误差不可校准）+ **宽度保证 SNR**（C0=12 超窄通道实测崩溃 77%，同架构全宽 C0=16 正常 92-96%）。

## 2. 硬件平台与部署架构

### 2.1 Gazelle 真机

| 项 | 数值 | 工程影响 |
|---|---|---|
| 物理计算 tile | 8×2 | im2col 展平长度尽量被 8 整除 |
| 原生精度 | 8a8w12o | int8 权重 + uint8 激活 + 12bit 输出 |
| 输入约束 | 非负、仅 MAC（无 bias）| bias=False + zero-point 反量化 |
| 校准基准 | compass_cali 后 EBR ≥ 8 | 放行判据之一 |
| 噪声结构 | per-column 偏移/增益 + per-element δW + iid | 校准修正列结构、REP 平均降 iid、δW 需训练鲁棒 |

### 2.2 两套部署路径

| | 路径 A：HTTP 远程客户端 | 路径 B：板端 numpy runner |
|---|---|---|
| 适用模型 | M1/M4/M5/M6/M7/M8 | M9/M10（ds3 系，conv3s2）|
| 架构 | 本地 torch（OpticConv2d/OpticLinear）+ 板上 server_gazelle.py（HTTP :8000）| 板上直接 compass_matmul（Python 3.6，无 torch）|
| 校准 | analyze_layers per-column affine npz（权重 md5 索引）| probe_dump_ds3 → calibrate_col.py 逐列 json |
| tiling | m≤1024 chunk | m≤2（FPGA 行回绕 bug）|
| 传输 | base64 二进制（2026-08-09 优化，~3× 提速）| 本地直连 |

## 3. 模型族设计（M1/M4-M10）

### 3.1 总览

| 模型 | 架构 | 参数量 | MACs/张 | v8 训练 test | **真机全量 5400** | 角色 |
|---|---|---|---|---|---|---|
| **M1** | Baseline VGG（flat+BN，6×3×3 + fc1/fc2）| 2.39M | **156.6M** | 变体 A：97.98 val / 97.87（QAT int8 val，部署参考）| **20/20 = 100%**（板端抽样 n=20）| 大参数/大计算量基准（真机全量不可行，抽样流程验证完成）|
| **M4** | MiniVGG-GAP（全 3×3 7 光算层 + GAP）| 260K | 17.03M | 96.17（v4.1）| **94.19%** | 复赛主力延续 |
| **M5** | J1-RF+（stem k5 + stage2 3×3×2）| 100,250 | 5.31M | 96.65 | 90.17% | 3×3 系代表 |
| **M6** | 纯 J1（全 1×1 (1,2,2)）| 50,330 | 1.38M | 95.22 | **92.78%** | ≤2M 预算 |
| **M7** | J1-w075（C0=12 + MaxPool）| 32,246 | 0.86M | 94.98 | 81.72%（板端 [0:1800]，架构不匹配）| 微型档（MaxPool 噪声偏传播，暂停）|
| **M8** | rf_stem5（J1 + stem k5）| 51,098 | 2.16M | 96.26 | 87.78% | 中间档 |
| **M9** | J1-w075ds3（w0.75 + conv3s2）| 54,886 | 1.52M | 95.87/95.69 | **94.43%** | ≤2M 冠军（最终交付）|
| **M10** | ds3pool3（conv3s2 + stem max3）| 96,602 | 2.56M | 96.76/96.56 | **95.33%（SOTA）** | v8 总冠军（X0）|

### 3.2 设计要点

- **M4**：7 光计算层（6×3×3 conv + head FC），stem FP32 电算（对齐率 84.4% 低、电算更高效）；
- **M5**：唯一在 8×8 低分辨率放 3×3 的模型（RF 49px）——决赛真机证明 3×3 层 δW 误差不可校准（全量 gap −6.3pt）；
- **M6**：全 1×1 光算层 + head/stem 电算——真机表现稳健（gap −2.7pt）；
- **M7**：C0=12 + MaxPool 下采样——路径 A 77.3% / 板端 81.72%（深诊断后暂停）；与 M9（同 C0=12、conv3s2）差 12.1pt（M9 94.43% vs M7 修复校准后最佳 82.33%；三段累计 [0:1800] 81.72% → 差 12.7pt），**最终判定为架构特性：MaxPool 取 max 对加性噪声有偏传播（选择噪声尖峰），卷积光层平滑噪声**；
- **M9/M10**：conv3s2 下采样（一份 MACs 同时答'下采样+RF+通道混合'），X0 B1 效率 0.55pt/M；路径 B + 逐列校准，真机全量 **M9 94.43% / M10 95.33%**（全模型 SOTA）——**最终交付模型**；M1 以板端 20 张抽样 100% 完成流程验证。

### 3.3 部署语义

- 光计算层：M5-M8 = 5×1×1 conv（stem/head FP32 电算，与 v8 训练 head_fp32 对齐）；
- M9/M10 = 7 光算 conv（s1a/s1ds/s2a/s2b/s2ds/s3a/s3b）+ h1/h2 光算（bias 反量化后加）；
- M4 = stem 电算 + 6×3×3 conv + head FC 光算（head bias 保留，C2 部署 bug 教训）。

## 4. 量化与噪声鲁棒训练（v8 QAT）

- **误差归因**（round5/X0）：hw 误差 95% 为 run 间可复现的**结构化分量**：per-column 偏移（4-23% 方差）+ per-column 增益（1-3%）+ per-element δW（21-50%）；
- **v8 配方**：训练时 per-batch 重采样三组分噪声 + iid σ=260，幅度取板上 probe 实测 × **1.5 余量**；60ep 从 clean ckpt 续训（M5-M8）或单阶段 160ep 从零（M9/M10）；
- **M5-M10 全部 v8 权重入库**（eurosat_research/weights/，git 强制跟踪），MD5 可校验。

## 5. 校准与部署链路设计

### 5.1 两套校准体系

| | 路径 A：analyze_layers | 路径 B：calibrate_col（C1 SOTA）|
|---|---|---|
| 形式 | per-column affine（a_j,b_j），权重 md5 索引 | 逐列 α_c/β_c，折叠进反量化 |
| 自检 | 无 | SE + 结构 SNR + 50/50 留出验证（方差改善 4.5-25.2%）|
| 纪律 | 同窗口背靠背 | **calib json 不可跨窗口复用**（实证 −24.4%→−7.8%）|

### 5.2 传输优化

- server_gazelle.py 支持 act_b64/weight_b64（base64，JSON 回退保留）：校准 503s→141s、跑批提速 ~3×；
- 客户端 gazelle_engine.py _b64_body 配套；run_eval.py REF 段修复（原硬编码 model2）。

## 6. 运行调度与器件保护

（2026-08-14 用户指令固化，AGENTS.md 第 9 条）

1. **单次调用（含校准）< 30min**：校准 ~10min，跑批 = 30 − 校准耗时；
2. **两次调用间 ≥5min 空余**（激光器冷却）；
3. **准确率比预期低 >5% → 冷却升级**（5min → 15-30min）并及时汇报；
4. **器件连续工作窗口 ~2h**（两次独立复现 0% 热崩溃）→ 窗口化跑批（每窗口 1-2 段 + 窗口间长冷却）；
5. **热崩溃恢复**：长冷却 ≥1h + fresh compass_cali（EBR ≥8 判据）。

> 共享板 SOP：开窗前四判据（EBR≥8 / error_std<±2%（10% 宽限）/ MNIST canary<0.5pt / EuroSAT 200 mini-run）+ who/ps 侦测 + 板上台账 BOARD_USAGE.md 登记。
